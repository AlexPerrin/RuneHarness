server-token-auth's rows a1-a6 and playable need an in-game token login without a mobile and without Jagex. Research by server-token-auth-4: with JX_SESSION_ID and JX_CHARACTER_ID set, the game client fetches its token from <jav_config param 11>game-session/v1/tokens and sends a token login; RSProx's own fake-account mode does the same (ProxyService.createProcess(useFakeJagexAccount), ProxyTarget.rebuildJavConfig params 11/22). The LOCAL_AUTH sidecar (server-tools/sidecar Http.kt AUTH_PARAMS 11,20,22,28; LocalAuth.gameToken) already answers game-session/v1/tokens. Blockers: OsrsTestLauncher exits when any JX_* variable is set and launches with no character; the server track's up runs the http sidecar with LOCAL_AUTH=false; the sidecar's tokens are lu-<hex>-<random>, not RS256 JWTs, while server-token-auth verifies RS256 JWTs (iss, aud, exp, sub = account name) against token-login issuer/audience/public-key in game.yml. Needed: tools/track.sh up <slug> with a token option starts a desktop whose login is a token login for its account, with the token minted by a local RS256 issuer whose issuer/audience/public key the up writes into the run's game.yml token-login block, plus a way to supply a chosen token (forged, expired, wrong audience) for the negative rows. Unchecked: whether the game code accepts an http:// param 11 and its response format (plain text vs JSON).

The user's word (2026-11-01): "Login was a pain point in v7, ensure our login automation is scripted and as quick as possible. Tie in with the token work to simplify the workflow, prefer devtools always." So: one scripted login path for every desktop and device, through the devtools login tool (no keystrokes, no screen points), fed by the compact token from the issuer (harness-desktop-token-login) where the server takes token logins and by the account's password otherwise; it ends on the devtools-read outcome (LOGGED_IN or the refusal code) with no fixed waits, clears the disconnected dialog through its widget, and up/restart/relogin all call that one path. desktop_login.py's keystroke code and the old mobile tap code are removed. Proof includes the time from client start to LOGGED_IN, recorded in evidence.

The user's word (2026-11-01): "Token auth should mimic official as close as possible." So the token flow follows the official game's as observed (RSProx recordings of the Android/Jagex-account login, the client's own jav_config params 11/22 requests and the game-session token endpoint's request and response shapes): the same endpoints and fields, a token of the official length and character set inside the RSA login block, the same login packet and auth type 7, and the official login responses for a bad, expired or unknown token. Where our design differs from the observed official one (today's <account>.<expiry>.<HMAC> token is our own shape), the difference is named in evidence and closed, or named as unsourced where no recording shows it.
