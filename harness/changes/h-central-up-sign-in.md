# tracks/central/track.sh up <slug> token: a server with token login whose desktop signs in through the head's Central

central-game-session (dev/central-game-session db30e21 on fork) serves the sign-in in Central: OIDC (/.well-known/openid-configuration, /oauth2/auth, /oauth2/token, /userinfo, /jwks) and game-session/v1 (sessions, accounts, tokens), on when Central's signIn.tokenSecret is set. Embedded Central (central.same-instance) reads it from the server's environment: OPENRUNE_SIGN_IN_TOKEN_SECRET (base64; the same value as game.yml token-login.secret), OPENRUNE_SIGN_IN_DEV_ACCOUNT (signs every sign-in in as that account, as issuer.py), OPENRUNE_HTTP_TLS_PORT, OPENRUNE_HTTP_TLS_KEYSTORE (a PKCS12 path inside the container), OPENRUNE_HTTP_TLS_KEYSTORE_PASSWORD. Its /jav_config.ws names its own base in params 11, 20, 22 and 28 with the scheme, host and port the jav_config was fetched on: the desktop fetches it over https (it casts 11 and 22 to https), the APK over http. No tool can prove it today: tracks/central/track.sh up builds the fork's upstream main (origin/main), which has no token login (TokenLoginVerifier is only on dev/server-token-auth, live on staging), and tracks/fork/track.sh up passes the server no environment, serves jav_config from the http-<slug> sidecar and runs token-<slug> (issuer.py) with JX_SESSION_ID=harness. Needed: tracks/central/track.sh up <slug> token builds staging (or the base carrying server-token-auth) with CENTRAL=<head>, sets the five env vars on server-<slug> (the secret from issuer.py key, a PKCS12 of its tls.pem/tls.key, the dev account = account 1), publishes Central's http and TLS ports, runs no token-<slug> and no http-<slug>, points the desktop's OPENRUNE_ENDPOINT at https://127.0.0.1:<tls>/ (trustStore as today), and sets JX_SESSION_ID from a real session (auth -> token -> POST game-session/v1/sessions against Central).
