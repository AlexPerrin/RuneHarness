# Requirements

The constraints every solution to docs/PROBLEM.md must satisfy, each derived from its principles. Code and tests cite the
ids. docs/ARCHITECTURE.md is the mechanism that meets each; docs/ACCEPTANCE.json is the checklist below as data, where
only `passes` may change.

| Id | Constraint | From |
|---|---|---|
| R1 **Goals** | Each goal is measured by its command whenever its target moves, shown with the tree it was measured on, and work is chosen to close the gap to its target. A server change unblocks the client once live on the test server. | P1 P10 |
| R2 **Flow** | A defined change reaches its live target with no person involved once the changes it depends on are live; a change the user closes takes no further step and leaves the integration tree; a done or closed change leaves no worktree or local branch. The orchestrator, a top-level session visible in the user's console, spawns and stops every run and is the user's chat: it shows cards, questions and alerts and acts on the user's other words; the user's yes and close are the user's own commands in that chat; with no orchestrator session the user is told to start one; its watch wakes it only when a line it acts on appears (spawn, card, question, alert); planning across tracks and the monitoring of operations belong to a planner run listed by facts; nothing depends on any session staying alive. | P3 P10 |
| R3 **Contract** | What ships is exactly what was checked and approved, against a contract written before the code: the track's seed rows, the accuracy spec, the live upstream rules with their blob shas, the user's answers and prior findings; a row is proved through the change's own tree, never through a change that depends on it. The hand-over passes every script row; the reviewer judges every row once, pass or fail, a row it did not check is not judged and never passes, and verdicts append; a text-only failure is fixed in place. A gate is bound to the tree it ran on, a verdict and an approval to the head and contract they cover, each void when its input moves. A claim with no record counts for nothing; an unknown fact stops a step. | P1 P2 P7 |
| R4 **Authority** | Only a write to OpenRune and a client release need the user. No agent credential can do either; the harness does them only at the approved head. A card the user declines is not shown again at that head. | P4 |
| R5 **Recovery** | Any failure is repaired in one pass with no user action; a repair is recorded only when its effect is observed, and one that recurs is raised once. Only what the user alone can decide or fix is raised, once per change. Nothing is decided from elapsed time. | P3 P5 |
| R6 **Economy** | A script runs before an agent, an agent before the user; nothing is checked twice for the same input; agents but the planner are bounded by one count; harness changes are dispatched first, then a change on a PR before new content, each change at the best priority of the changes it blocks, and no run is listed for a change below the band the user holds until the user lifts it; the pass acts and logs only when a change's state changes; a run hands off to a fresh run at the context limit; a run keeps a desktop up only while it plays in it; bring-up, scenarios and lookups are scripts. | P5 P8 P9 |
| R7 **Visibility** | `hd` prints what to spawn, the cards and questions waiting, what runs, each goal's number with its tree, and the facts of every open change, derived; nothing else. Every run is an agent of a visible session. | P10 |
| R8 **Trees** | A change's tree T is its base, its dependencies and its head merged, a carried tools head rebased onto its moved branch; a conflict is the dev's step, and a resolution against a permanent pin is a merge ref bound to both heads, used by the integration tree only. The integration tree merges the pins, then the gated heads by priority and creation; a head's conflict is its own dev step and leaves it out while the rest deploy; a pin's conflict, with the base or another head, holds the deploy and is the dev step of the oldest gated change at it; one pass names every conflict. A server change's T includes the Central tree of its central dependencies, a central change being live once gated. T is built at most once, in a copy no agent commits from; its artefact serves the dev's check, the gate, the review and the deployment. The game cache is rebuilt only when its inputs change. Every artefact and process is named after its change or run; a game client is a mobile (the official Android app on an emulator) or a desktop (RuneLite on Windows), by that word alone. | P6 P9 |

Nothing contacts Jagex: every mobile the client track boots resolves no hostname, checked by its `up`. Constraints
that need no mechanism: the user's own RuneLite and the tester account are never touched (A10). Each track's seed rows and the dev's and reviewer's rules live in each repo's `tools/track.md` and `.claude/skills/`.

## Acceptance

Each check is a command. `python3 -m unittest tests.test_hd.<R>` runs the requirement's class against fakes of git,
gh, docker and the process table; a live check reads the real state.

1. **R1** `tests.test_hd.R1`: a target move lists the measure step once; the measurement is bound to the target's tree;
   a goal dependency neither live nor closed holds its measure;
   a server head live on the test server unblocks the client changes depending on it; a passing verdict on a live change marks the units it names, and only then; below target with nothing open a planner run is listed. Live: `hd` shows each goal's
   number with a tree equal to its target's current tree.
2. **R2** `tests.test_hd.R2`: a change with a live dependency goes from defined to live with no `approve`, `answer` or
   console call; a closed change lists no run and leaves T_int; a done or closed change ends its runs, a started one with its record and an ended event, and a closed dependency holds nothing; a fresh dev ref the base contains is neither live nor done until handed over; a done change's worktrees and local branches go in each repo, the dev ref last and still done, a branch no live branch holds stays unless the change is closed, remote refs are never touched, a failed removal is raised once; `hd` lists a spawn exactly while an agent step is unmet and no run is alive for its input, a run being alive through its idle stops until the stop after its hand-back, an idle stop refused while a background command or monitor it started has not reported its end, and its record newer than its change's last answer; an alert an open change carries or a planner hand-back answered lists no planner until the trigger changes (a gate failure at a new T, an alert with a new count), and a gate failure lists none while it is its dev's (no dev run handed back on that T, or a run of the change alive); `hd` lists no relayed message and `hd tell` is no command, the orchestrator's brief carries the card, question and alert steps; with no `claude --agent orchestrator` process the user is told to start one, and no planner is listed for it; a pass rewrites `state/wake.orchestrator` only when a spawn, card, question or alert line appears, a repeated line not waking it.
3. **R3** `tests.test_hd.R3`: a change without a contract lists the contract step and no dev; a hand-over with a failing
   script row, or whose pushed ref is not the head it names, is refused; a harness hand-over reads its local dev ref, never a pushed one; a script row the user's answer waives is not run; a verdict missing a row, or with a row not judged and none failing, is refused, and the next brief lists the open rows; a contract row needs no change depending on its own; verdicts
   append; a text-only fix leaves the verdict at the same head valid; a gate at T does not hold at T'; a verdict at H
   does not hold at H'; a harness change's tools commits are handed over, gated and landed with it; a moved upstream rule file voids only the rule rows; a failed fetch leaves every change where
   it was. Live: every `evidence/<slug>/contract.md` row has an id and a result.
4. **R4** `tests.test_hd.R4`: the upstream and release steps run only after an approval at that head; `hd decline` hides the card at that head; a central change goes
   to Central's upstream through its own fork. Live: `gh auth
   status` in an agent's shell shows the token scoped to AlexPerrin/*; `sudo -n -l` lists only the public-act helper
   under user `hd`; `hd approve` or `hd close` from a subagent or the orchestrator session is denied, while the user's own `!` command fires no hook.
5. **R5** `tests.test_hd.R5`: console gone → its runs end and their artefacts are removed in one pass; a run the orchestrator stops (`hd stop`) ends and frees its slot; a dead ship
   process → rerun; a script dead twice on the same args → raised once, a new args or a landed result restarts the count; a yes recorded then the orchestrator gone → the ship completes; a repair whose effect is not observed is not
   logged; the same repair twice raises once; a second `hd ask` on a change with an open question is refused, and an open question holds the change (no run, gate, ship or upstream step) until its answer; a fix a dev
   files with `hd new --blocks` holds the change with no question raised; a repo without the noreply git identity gets it in one pass, so its clones commit with no per-run env; docker not answering → one alert, no script starts and no run that builds or tests (a code or judge run off the harness track) is listed, an unspawned one ends, and it is listed again once docker answers.
6. **R6** `tests.test_hd.R6`: the same T never builds or gates twice; the same head and contract never judge twice;
   no more than the configured agents are listed, the planner outside that count; with a band held, no run is listed for a change below it, a listed one is dropped, and a blocker raised into the band still runs; two passes over unchanged facts append no event; a run over the
   context limit is told to start no new work and hand off cleanly (commit and push its work in progress, record what it judged, collect its subagents and stop its processes, write the hand-off file), and its successor is listed with the hand-off file and that commit; three runs of a change past it since its last handover or the last planner run that handed back on that alert are raised; a session of no run past it is told nothing; a run whose desktops are up through a stretch of tool calls with no devtools call is told once to bring them down, the count starting again at its next devtools call or up; every run record carries
   its usage and transcript. Live: `tools/track.sh up <slug> 2` prints two logged-in desktops' ports and returns.
7. **R7** `tests.test_hd.R7`: `hd` output contains only spawns, cards, questions, runs, goals and change facts, and
   prints no step name as a state. Live: `python3 hd.py` on the real state.
8. **R8** `tests.test_hd.R8`: T is `git merge-tree` of base, deps and head; a server change's key and `CENTRAL` carry the
   merge of its central dependencies, and T_int the one of its heads'; a conflict lists the dev; a carried tools head its branch moved past is
   rebased by the pass and re-gated, a conflict listing the dev; a merge ref
   `local/merge/<a>-<b>` stands in for heads a and b (the base one of them) in T_int and is ignored once either moves; a
   pin's conflict lists the dev of the oldest gated change at its deploy step; T_int merges heads by priority, then creation, and a
   lower-priority head's conflict lists its dev while the higher-priority heads deploy; one T_int pass names every conflicting head
   (each left out, the rest merged on) in one dev run, with hd's merge order; build(T) runs once
   per T and in the change's build copy; the dev's clone is clean after a build; the cache step runs only when its
   input hash changes; every container, volume, clone, mobile and desktop is named by its change or run. Live:
   `tools/track.sh build <slug>` twice prints `cached` the second time.
